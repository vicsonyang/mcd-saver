# 券规则

## 一、三层券，只有最后一层能算价

| 层 | 接口 | 用途 | 能否算价 |
|---|---|---|---|
| 卡包资产 | `query-my-coupons` | 提醒与过滤 | 不能，返回是文本且无券 ID，且明确不做门店与渠道校验 |
| 可领取 | `available-coupons` | 判断领什么 | 不能，同样无券 ID |
| 门店可用 | `query-store-coupons` | 算价 | **能**，唯一可信来源 |

拿卡包券直接算价必错。

## 二、自动领券

调用 `auto-bind-coupons`，前后各调一次 `available-coupons`，以"可领取"条数的差值判定本次新领到几张。重复调用不报错，不重复汇报同一批券。

首次使用时询问一次授权，回答写入用户档案的 `autoBindCoupons` 字段：

- `true`：此后静默执行，在方案末尾汇报领到什么
- `false`：此后每次询问；用户明确说别再问则永久跳过该环节

领券不花钱、不产生负债、不锁定履约义务，因此授权后无需逐次确认。但必须汇报结果，因为有效期从领取那一刻起算。领到零张时不得宣称"已为你自动领券"。

## 三、可用性过滤

券带两个额外维度，必须过滤，否则会出现"看着有券、算完没优惠"：

```
1. 渠道过滤：选到店剔除"外送专用"，选外送剔除"到店专用"
2. 星期过滤：券的适用星期不含今天则剔除
3. 时段过滤：当前时间不在券的时间窗内则剔除
4. 过期过滤：结束时间早于当前则剔除，并计入已过期提醒
```

输入为卡包文本、服务器时间与星期、当前渠道。输出为今日此刻真实可用券清单，以及三天内到期清单。

兜底：

- 文本解析失败时不猜，以 `query-store-coupons` 结果为准
- 服务器时间获取失败时用本机时间，并标注时间源不可靠
- **过滤后为零张不是异常**，走无券价最优分支，同时提示换渠道或换时段可能更省

## 四、挂载方式

券挂在 `items[]` 的单个商品上，不存在订单级整包券参数。

```
正确  items[i] = { productCode: A, quantity: 1,
                  couponId: xxx, couponCode: yyy }
错误  { items: [...], coupons: [全部可用券] }
```

挂载依据是 `products[].productCode`，精确已知，不需要遍历"哪张券挂哪个商品"的排列组合。真正要枚举的只有"本次用哪张券"。

## 五、一个订单只能用一张券（2026-10-13 实测）

实测把三张券分别挂在三个不同商品上提交算价，服务端直接拒绝：

```
success: false
code:    600022
message: 暂不支持多张券使用
```

结论：**跨商品分发同样不被支持**。此前"各挂各的是接口结构天然支持"的判断是错的，两种叠加一律被拒。

由此带来的简化：

```
1. 券维度不需要组合枚举，退化为"从 N 张可用券里单选最划算的一张"
2. 不需要试探性多次算价去标定上界，上界恒为一
3. 算价调用预算可以全部投向"不同商品组合 × 不同单券"的横向比较
```

仍保留一次实测的前提：该结论带日期，超过三十天按第七节规则重测一次。

## 六、券是加购型，不是减价型（2026-10-13 实测）

券的 `products[].productCode` 指向的是一个**独立商品**，不是已有餐品的折扣项。实测三张券的抵扣全部落在加购商品上：

| 券 | 加购商品原价 | 券后 | 抵扣 |
|---|---|---|---|
| 中薯条买一送一 | ¥29.00 | ¥13.50 | ¥15.50 |
| 9.9 元中杯冰美式 | ¥19.00 | ¥9.90 | ¥9.10 |
| 王牌小食拼 | ¥24.00 | ¥15.90 | ¥8.10 |

含义：

- 挂券**不会降低**订单里原有餐品的价格，只是让你低价多买一件东西
- 因此"省了多少"必须区分两种口径：券的抵扣额，以及相对于不加购时的实付增量
- 追求实付最低时，**不挂券的裸单往往更便宜**，必须把裸单作为一个候选参与排序，不能默认挂券即更省

另一个实测事实：券商品的 `productCode` **可以不在 `query-meals` 返回的菜单里**，直接作为 `items[]` 的一项提交仍然算价成功，价格照常返回。不需要因为菜单里查不到就判定券不可用。

## 七、叠加结论缓存

以"券 A 加券 B"为键写入用户档案，下次遇到同一对券直接用结论，不重复试探。条目带实测时间，超过三十天视为失效需重测。

当前缓存（2026-10-13 实测于门店 1400364 / 麦乐送）：

```
中薯条买一送一 + 9.9元冰美式    互斥  600022
中薯条买一送一 + 王牌小食拼      互斥  600022
9.9元冰美式    + 王牌小食拼      互斥  600022
任意两张及以上                    互斥  600022（上界恒为一）
```

缓存键也可以只用"订单级"这一个：既然上界恒为一，遇到两张券时无需查表即可直接判定不可同用。
